# 设计说明

## 目标

做一个公开的状态页，让玩家看《燕云十六声》现在能不能登录，还有近 30 天的可用情况和停服、异常记录。全部用免费托管服务，不用自己买服务器，也省了备案。

## 数据来源

- **服务器列表**：`https://h72.update.nieapps.com/server_list_prod_b.txt`，游戏登录前读的就是这份。纯文本，一行一个入口，11 列：区名、_、组号、_、_、_、服名、`ip:端口:_:_`、服号、主控域名、_（_ 是含义不明、程序也没用到的列）。
- 列表里有 65 台服务器（单人服 50 台、大世界服 15 台），每台有 7～9 个端口。游戏登录时从全表里随便挑一个入口，端口再加 0～15 的随机偏移。入口之间可以互换，从任何一个进去都会被转到玩家角色所在的服。
- 同目录还有一份 `server_list_prod_a.txt`，指向预发布环境，正式服不用。
- 列表里找不到表示维护的字段，所以停服只能靠握手来判断。实际测过，停服时入口端口会直接丢包，握手会超时。

## 组成

| 部分 | 放在哪 | 干什么 |
|---|---|---|
| 探测 | GitHub Actions（公开仓库） | 每 5 分钟跑 `probe.py`，每台服务器握手一次，把结果提交回仓库 |
| 页面 | Netlify | 静态页，只部署一次 |
| 数据传递 | Netlify 反向代理 | `/data/*` 代理到 `raw.githubusercontent.com` 上本仓库的文件 |

为什么这么搭：

- 公开仓库跑 GitHub Actions 不限时长，我本机的 `gh` 也已经登录，不用另开账号。每次运行都会提交数据，仓库一直有动静，所以不会因为 60 天没活动被停掉定时任务。
- Netlify 在国内访问顺畅。`raw.githubusercontent.com` 在国内经常打不开，所以交给 Netlify 在海外去取。
- 因为页面不跟着数据重新部署，所以碰不到 Netlify 的部署次数限制，GitHub 那边也不用存 Netlify 的密钥。

已知代价：

- GitHub 的定时任务经常推迟或跳过，实际间隔是 5～15 分钟。数据超过 30 分钟没更新时，页面会提示。
- 探测是从海外发起的。如果网易丢弃海外的连接，页面会一直显示停服。到时候的退路是把 `probe.py` 放到国内的机器上定时跑，再把 `data/` 推上来。

## 判定规则

| 状态 | 条件 |
|---|---|
| `up` 运行正常 | 能连上的服务器 ≥ 90% |
| `partial` 部分异常 | 低于 90%，但至少有一台能连上 |
| `down` 停服中 | 一台都连不上 |
| `unknown` 检测失败 | 服务器列表没拉到 |

- 每台服务器测列表里的第一个端口。失败的补测一次，两次都失败才算连不上。
- 连续的非 `up` 记录合成一次事件，最差的状态记在 `worst`。`unknown` 记录直接跳过，既不开始也不结束事件。
- 按北京时间分天，统计每天的检测次数、`up` 占比和最差状态。

这些规则写在 `test_probe.py` 的用例里。

## 数据格式

`data/history.jsonl` 每行是一次检测：`{"t": 时间戳, "ok": 能连上的台数, "total": 总台数, "s": 状态}`。

`data/status.json` 是页面要用的全部数据：当前状态、每台服务器的结果（服名、通不通、延迟，不含 IP）、近 30 天按天汇总、最近 20 次事件。每次检测都由 `history.jsonl` 重算一遍。

## 页面

页面就一个 HTML 文件，没引用任何外部字体和脚本。从上到下依次是当前状态、登录服务器方块、近 30 天柱状图、停服和异常记录，页脚注明了非官方、以官方公告为准。页面每 2 分钟自动刷新一次，时间全部按北京时间显示。

如果一条事件从第一次检测起就已经不正常，真正的开始时间不知道，页面就写「开始检测时就已经是这样了」，不写开始时间和持续时长。
