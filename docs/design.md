# 设计说明

## 目标

公开一个状态页，让玩家看《燕云十六声》现在能不能登录、近 30 天的可用情况和停服记录。不上服务器、不办备案，全用免费托管。

## 数据来源

- **服务器列表**：`https://h72.update.nieapps.com/server_list_prod_b.txt`，游戏登录前读的就是这份。纯文本，一行一个入口，11 列：区名、_、组号、_、_、_、服名、`ip:端口:_:_`、服号、主控域名、_。
- 列表里有 65 台机器（单人服 50 台、大世界服 15 台），每台 7～9 个端口。游戏登录时从全表里随便挑一个入口，端口再加 0～15 的随机偏移；入口之间可以互换，任何一个都能把玩家转到自己角色所在的服。
- 同目录还有一份 `server_list_prod_a.txt`，指向预发布环境，游戏正式服不用。
- 列表里没有表示维护的字段，停服只能靠握手判断。停服维护时入口的端口会直接丢包，握手超时。

## 组成

| 部分 | 放在哪 | 干什么 |
|---|---|---|
| 探测 | GitHub Actions（公开仓库） | 每 5 分钟跑 `probe.py`，每台机器握手一次，把结果提交回仓库 |
| 页面 | Netlify | 静态页，只部署一次 |
| 数据传递 | Netlify 反向代理 | `/data/*` 代理到 `raw.githubusercontent.com` 上本仓库的文件 |

选这套的原因：

- GitHub Actions 公开仓库不限时长，本机 `gh` 已登录，不用新开账号；每次运行都会提交，仓库一直有动静，不会触发「60 天无活动停用定时任务」。
- Netlify 在国内访问顺畅；`raw.githubusercontent.com` 在国内常打不开，交给 Netlify 在海外去取。
- 页面不随数据重新部署，不受 Netlify 部署次数限制，也不用在 GitHub 存 Netlify 密钥。

已知代价：

- GitHub 定时任务常常推迟或跳过，实际间隔 5～15 分钟；页面在数据超过 30 分钟没更新时会提示。
- 探测从海外发起。如果网易丢弃海外连接，页面会一直显示停服；退路是把 `probe.py` 放到国内的机器上定时跑，推送 `data/`。

## 判定规则

| 状态 | 条件 |
|---|---|
| `up` 运行正常 | 能连上的入口 ≥ 90% |
| `partial` 部分异常 | 介于两者之间 |
| `down` 停服中 | 0 台能连上 |
| `unknown` 检测失败 | 服务器列表没拉到 |

- 每台机器测列表里的第一个端口；失败补测一次，两次都失败才算连不上。
- 连续的非 `up` 记录合成一次事件，最差状态记在 `worst`；`unknown` 记录跳过，既不开始也不结束事件。
- 按北京时间分天，统计每天的检测次数、`up` 占比和最差状态。

规则钉在 `test_probe.py` 里。

## 数据格式

`data/history.jsonl` 每行一次检测：`{"t": 时间戳, "ok": 能连上的台数, "total": 总台数, "s": 状态}`。

`data/status.json` 是页面要的全部东西：当前状态、每台机器的结果（服名、通不通、延迟，不含 IP）、近 30 天按天汇总、最近 20 次事件。由 `history.jsonl` 每次重算。

## 页面

单个 HTML 文件，不引用任何外部字体和脚本。顶部大状态，下面依次是入口机器方块、近 30 天柱条、停服记录，页脚注明非官方、以官方公告为准。每 2 分钟自动刷新。时间一律按北京时间显示。
